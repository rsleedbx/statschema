# Databricks Lakebase

← [All databases](../local-databases.md)

**Method:** Databricks managed Postgres · **Port:** 5432 · **Driver:** `psycopg2-binary` · **Auth:** OAuth token via `databricks-sdk`

Lakebase uses the PostgreSQL wire protocol, so the existing `postgres` dialect handles all DDL emission, schema collection, and stats injection. Authentication uses short-lived OAuth tokens generated by the Databricks SDK instead of a static password.

> Replace `DEFAULT` with your profile name if using a named profile in `~/.databrickscfg`.

---

## Prerequisites

```bash
pip install 'statschema[lakebase]'   # databricks-sdk>=0.89.0 + psycopg2-binary
```

Workspace auth via `~/.databrickscfg` (interactive) or environment variables (CI):

```bash
# Service principal — CI/CD
export DATABRICKS_HOST=https://your-workspace.cloud.databricks.com
export DATABRICKS_CLIENT_ID=<sp-client-id>
export DATABRICKS_CLIENT_SECRET=<sp-oauth-secret>
```

## Start the endpoint

`scripts/lakebase-up.sh` creates the project and endpoint on first run, then re-enables it on subsequent runs. All connection details are written to `.env`.

```bash
./scripts/lakebase-up.sh
# → Writes STATSCHEMA_LAKEBASE_ENDPOINT, HOST, DB, USER to .env
```

The script uses the `DEFAULT` profile. To use a different profile:

```bash
DATABRICKS_PROFILE=ci ./scripts/lakebase-up.sh
```

---

## Connection details

After `lakebase-up.sh` runs, `.env` contains:

```bash
STATSCHEMA_LAKEBASE_ENDPOINT=projects/<proj>/branches/production/endpoints/primary
STATSCHEMA_LAKEBASE_HOST=<ep-id>.database.<region>.cloud.databricks.com
STATSCHEMA_LAKEBASE_DB=databricks_postgres
STATSCHEMA_LAKEBASE_USER=<user-email-or-sp-client-id>
```

## Run the live tests

```bash
make test-live-lakebase
```

This runs `lakebase-up.sh`, executes `tests/test_live_lakebase.py`, then calls `lakebase-down.sh` to disable the endpoint.

## Collect DDL and statistics

**CLI:**

```bash
source .env
statschema collect --dialect lakebase \
    --endpoint "$STATSCHEMA_LAKEBASE_ENDPOINT" \
    --host "$STATSCHEMA_LAKEBASE_HOST" \
    --user "$STATSCHEMA_LAKEBASE_USER" \
    --catalog databricks_postgres --schema public --tables '%'
```

**Python SDK:**

```python
import os
from dotenv import load_dotenv
from databricks.sdk import WorkspaceClient
import psycopg2
from src.statschema import collect_table_stats, dump_stats, DatabaseStats

load_dotenv()

w = WorkspaceClient(profile="DEFAULT")
creds = w.postgres.generate_database_credential(
    endpoint=os.environ["STATSCHEMA_LAKEBASE_ENDPOINT"]
)
conn = psycopg2.connect(
    host=os.environ["STATSCHEMA_LAKEBASE_HOST"],
    port=5432,
    dbname=os.environ.get("STATSCHEMA_LAKEBASE_DB", "databricks_postgres"),
    user=os.environ["STATSCHEMA_LAKEBASE_USER"],
    password=creds.token,
    sslmode="require",
)

tables = ["orders", "order_details"]
stats = [collect_table_stats(conn, t, dialect="postgres", schema="public") for t in tables]
dump_stats(DatabaseStats(tables=stats), "lakebase_stats.yaml")
```

## Teardown

Disable the endpoint (data preserved, zero compute cost):

```bash
./scripts/lakebase-down.sh        # or: make lakebase-down
```

Delete the project permanently:

```bash
./scripts/lakebase-down.sh --destroy   # or: make lakebase-destroy
```

The next `make test-live-lakebase` or `lakebase-up.sh` call re-enables the endpoint automatically.

---

## Notes

- OAuth tokens have a 60-minute lifetime. `_lakebase_connect()` in `cli.py` generates a fresh token on every connection.
- Lakebase does not support deleting the `primary` read-write endpoint. `lakebase-down.sh` disables it instead of deleting it.
- The `databricks postgres` sub-commands require Databricks CLI ≥ 0.223.
